## 配置与资源

- 48 kHz、单声道。保留浏览器 AEC；关闭浏览器 NS / AGC，只运行一个自定义降噪器。使用既有输入增益，不叠加模型自动增益。
- 模型讲话衰减限制 25 dB；内部停顿门控额外 20 dB，一帧前瞻（10 ms）。这些是配置值，不是本机噪声抑制测量结果。
- 固定 `@workadventure/noise-suppression@0.2.0` 的原始 worklet、WASM 和 DeepFilterNet3 模型；没有安装整个 152 MB npm 包，也没有替换 RNNoise 库或模型。
- 运行文件分别为 21,759、14,643,565、7,983,136 字节，合计 22,648,460 字节（约 22.65 MB）。页面提示首次加载约 23 MB；网络压缩和缓存会影响实际传输量。
- 只有选择增强档并开始采集时才加载模型，资源来自本站，无音频云服务。成功资源在当前页面缓存；下载、哈希检查、编译失败或取消不写入成功缓存。
- 下载带 20 秒截止与取消信号，初始化、模块加载也有限时；WASM 和压缩模型先做 SHA256 校验再使用。服务端必须原样提供模型 `.tar.gz`，不能再标记 `Content-Encoding: gzip` 导致浏览器自动解压。
- 新运行资源都在既有 `src/` 发布白名单内，是增强档运行所需文件，无需扩大服务端 ZIP 白名单。源码资源增加约 23 MB；本轮没有打包。

资源与许可记录：`src/views/vendor/deepfilter-0.2.0/README.md`、`manifest.json`、封装 MIT LICENSE，以及 `src/views/wasm/deepfilter-0.2.0/` 的 libDF MIT / Apache 文本。manifest 固定文件哈希、npm 源版本和提交。

上游：[浏览器封装及源码](https://github.com/workadventure/noise-suppression/tree/7e00a1b7522f044a31776fddc249a97a98de94ed)、[DeepFilterNet 核心](https://github.com/Rikorose/DeepFilterNet)。

## 切换与恢复

- 模型处理使用独立 AudioContext，经内部 MediaStream 接入原有输出上下文。切走、取消、失败和退出时停止内部轨道并关闭模型上下文，避免在长期上下文里反复积累模型内存。
- 保留通话输出轨道及静音标记，不要求退出重进、不改 Peer/频道成员关系；不触碰摄像头或共享轨道。
- 候选加载/初始化失败时释放候选、恢复旧采集约束，保留原音频，并回滚模式选择。
- 运行中的 `error`、`processorerror` 或持续过载报告触发同轨道直通恢复，保留 AEC 和输入增益，界面显示回退原因，用户可再选择 RNNoise。没有静默宣称增强档仍在生效。
- 旧处理器在新设置采集等待中报错，也允许先恢复旧分支的直通，不让等待中的切换阻塞恢复；新设置继续按原事务处理。
- 快速切换、取消或离开后的迟到结果不得接管新配置。DeepFilterNet3 的内部停顿门控不由 RNNoise 复选框控制。

### 耗时与延迟的边界

Node VM 短探测使用实际上游 worklet / WASM 与合成双音：初始化约 272 ms、WASM heap 29,949,952 字节；128 样本调用 p95 约 1.17 ms。独立 RNNoise 480 样本模型调用 p95 约 1.02 ms。二者统计单位不同，不能直接比较为质量或整条链的 CPU 优势。

隐藏 Chromium 的 OfflineAudioContext 合成扫频相关分析，增强处理器信号滞后约 **50.67 ms**（相关系数约 0.93），不包含跨上下文桥接、采集、网络和物理输出设备延迟。RNNoise 的同一合成信号相关系数只有约 0.18，其约 30.67 ms 的峰值不作为可靠延迟基准。

真实 worklet 的短窗口处理负载会随并发任务变化：单独验证约 15%–16%，与完整测试并行的一次记录约 26%，且有较多超 3 ms 帧。这些是合成输入下的短期模型处理统计，不能保证低配机器无杂音或代表实际语音 CPU。上游平均过载监测保留，实验档仍需真实设备压力与听感验证。
