### SFU 屏幕转发配置（20 Mbps 出口 / 1 GB 内存候选）

新实现保留语音和摄像头的 P2P 路径，屏幕视频与屏幕声音优先使用 mediasoup SFU。服务器只转发，不做视频转码。浏览器 SDK 和依赖许可证已放在 `src/views/vendor/`，属于现有 `src/` 白名单；服务器无需执行前端构建。

1. SFU 要求 **Node.js 22 或更新版本**。在新版本目录执行 `npm ci --omit=dev`。mediasoup 为可选依赖，安装或 worker 启动失败时回到 P2P；必须检查启动日志，不能把依赖安装成功等同于 SFU 已启用。安装优先下载平台对应的预编译 worker；若开始本机编译，1 GB 服务器可能内存不足，应在相同平台/架构的构建环境准备 worker，参考 mediasoup 的 `MEDIASOUP_WORKER_BIN` 配置，不上传 Windows 的 `node_modules` 到 Linux。
2. 经发布者确认后，在服务器 `.env` 中添加或核对下列字段（本地实现不会自动修改线上配置），将地址改成服务器的公网 IP：

   ```dotenv
   SFU_ENABLED=true
   SFU_ANNOUNCED_ADDRESS=服务器公网IP
   SFU_LISTEN_IP=0.0.0.0
   SFU_PORT=44444
   SFU_EGRESS_MBPS=20
   SFU_RESERVED_MBPS=4
   SFU_VIDEO_MBPS=15
   SFU_PAYLOAD_MBPS=16
   SFU_INITIAL_VIEWER_MBPS=5.5
   SFU_MEMORY_LIMIT_MB=700
   SFU_CPU_LIMIT_PERCENT=85
   ```

3. 云安全组与系统防火墙都放行 **44444/UDP 和 44444/TCP**。如果主机有 NAT，两个协议的外部端口都映射到同一内部端口。网站仍通过现有 HTTPS 反向代理访问；HTTP 反向代理不会转发这条媒体路径。SFU 使用 WebRTC 的 DTLS/SRTP 加密，无需额外把网站证书复制给 worker。

- 复用每两秒采样，读取发送源实际码率、去重后的接收 Transport 总出站（含重传/探测）及 Linux 默认出口网卡真实发送字节增量；网卡统计包含其他站点。未知、计数器重置、重复时间戳不冒充真实零值。账本不足、统计失效或观测总出站超过 16 Mbps 时暂停新 SFU 接入，保留已有观看。估算上涨本身不踢人；实际连续三个采样超额才将最新一条订阅回退 P2P，两次释放至少间隔 15 秒。连续三次低于预算 90% 才恢复接入。保留原有接收异常冷却和重试，不平均削减已有观看者的源画质。

- P2P 一两人且没有 SFU 上传时保留原 27 Mbps 高上限；多人或同时存在 SFU 上传时，扣除估计 SFU 上传后再分配直连视频预算。P2P 能否接入仍取决于网络穿透与共享者上行，无法保证任何网络下后来者都获得相同画质。
- CPU、Node 与 worker 内存峰值、系统剩余内存有保护阈值。连续三次资源采样超限会回到 P2P。1 GB 内存是否够用，需要在同时运行其他项目的真实服务器验证。
- 观看端收到并解码 SFU 视频后才停止其重复 P2P 发送。已连接的 P2P 视频 sender 保留空槽，SFU 或整个服务进程停止时可恢复发送；新加入者和需要重新协商的连接仍需要信令服务器恢复。
- 观看端每两秒检查实际解码进度。共享源仍在发送、页面在前台且连续三次低于 5fps 时，释放该观看者的 SFU 路径并恢复原始采集画面的 P2P，不降低分辨率或帧率目标。静止源、后台页面不据此切换；连续三次统计超时也恢复直连。同一共享两分钟内不重试 SFU，避免来回切换。
- 观看者诊断新增“观看路径”和所选媒体连接的 UDP/TCP 协议信息，便于区分服务器转发与 P2P；不导出候选地址。

## 可选 TURN 中继

应用支持 coturn 的 REST 临时凭据模式，默认保持关闭。配置不会安装或启动 TURN，也不会把 Node HTTP 反向代理变成媒体中继。

在服务器现有 `.env` 中成对配置 `TURN_URLS`（例如 `turn:turn.example.com:3478?transport=udp,turns:turn.example.com:5349?transport=tcp`）与 `TURN_SHARED_SECRET`；密钥为 32–1024 字符，必须与 coturn 的私有 `static-auth-secret` 一致，coturn 使用 `use-auth-secret`。不要提交真实密钥或写进 `.env.example`、HTML、截图、日志或候选包。`TURN_TTL_SECONDS` 默认 3600，允许 600–86400 的整数秒。无效 URL、单边配置或无效有效期会在 Node 监听之前阻止启动，错误消息不回显配置值。

浏览器加入语音前通过 `rtc:ice` 获取配置，在剩余有效期约四分之一时刷新，失败每 30 秒重试。每次新建发送连接或应答来电前也会检查有效期；已过期或剩余不足 10 秒时等待刷新，失败提示新连接正在重试，保留现有通话。签发恢复后自动重试待发送媒体；已关闭的来电不会因迟到结果重新应答。服务器使用 HMAC-SHA1/Base64 签发，用户名包含到期秒数及随机标识，不包含名字、IP、房间或 socket ID。每条 socket 每分钟最多 6 次请求，每个 Node 进程每分钟最多 120 次新签发；复用仍有超过半期有效时间的凭据，断开时清理缓存及请求限流记录。浏览器离开语音时取消刷新并拒绝迟到结果；刷新只更新 PeerJS 后续新建连接的配置，不关闭现有通话。仅页面声明了 TURN 启用时才启动这条流程；配置从关闭改为启用后需要刷新页面。

站点当前支持匿名访问固定频道。合法频道的匿名 socket 可请求临时凭据，频道校验不是账号认证，短期凭据仍可在到期前被持有者使用。签发限流不等于中继出口限速；实际 coturn 需要根据已有容量设置会话、总量及带宽配额，限制其可访问的目标网段。若要只允许指定账号使用中继，必须先接入账号授权，不能把本功能作为私有 TURN 的身份门禁。

上线验收需要确认 Web 页面通过 HTTPS/WSS 传送临时凭据、Node 与 coturn 时间一致、TURN 监听及媒体中继端口实际可达、`turns:` 的证书有效；使用实际受限网络或独立测试中的 `iceTransportPolicy: 'relay'` 验证候选类型为 `relay`，并确认双端音视频数据持续增长。再测超过凭据有效期的通话、新观看者、断线后重建和屏幕 SFU→P2P 恢复。正常应用仍优先直连，不会强制所有流量通过 TURN。`/readyz` 仅验证配置的媒体服务启动状态，**不验证 TURN 分配或公网中继**。

本地凭据签名、Socket.IO、浏览器配置和状态机测试均不能证明实际 TURN 中继成功；本轮未提供真实中继地址、凭据、服务安装或生产配置。Piik 内部媒体协议有独立配置，本功能只为现有 PeerJS 的麦克风、摄像头和 P2P 媒体连接提供 ICE 配置。

参考：[WebRTC TURN 说明](https://webrtc.org/getting-started/turn-server)、[coturn REST 凭据协议及服务选项](https://github.com/coturn/coturn/blob/master/README.turnserver)、[PeerJS 的 RTCConfiguration 入口](https://peerjs.com/client/api/peer)。
