## 1.0.1 共享诊断验收

共享开始后，在共享窗口右上方展开“共享诊断”。默认收起，展开时才读取统计；等待至少两次采样再在模糊/卡顿发生时点击“复制脱敏诊断”。共享者与观看者各复制一份，以区分发送编码、带宽和接收解码问题。数据只复制到剪贴板，不上传服务器；复制失败可手动选中面板文本。

`null` 表示首次采样、缺少字段或浏览器不支持，不是零。码率和丢包率按相邻采样计算；发送端的丢包为远端反馈累计值，接收端另有区间丢包率。`none/cpu/bandwidth/other` 分别为未受限/算力/带宽/其他。诊断只读，不改变编码、码率或传输策略。真实双端画质仍需发布后验收。

### SFU 屏幕转发配置（20 Mbps 出口 / 1 GB 内存候选）

新实现保留语音和摄像头的 P2P 路径，屏幕视频与屏幕声音优先使用 mediasoup SFU。服务器只转发，不做视频转码。浏览器 SDK 和依赖许可证已放在 `src/views/vendor/`，属于现有 `src/` 白名单；服务器无需执行前端构建。

1. SFU 要求 **Node.js 22 或更新版本**。在新版本目录执行 `npm ci --omit=dev`。mediasoup 为可选依赖，安装或 worker 启动失败时回到 P2P；必须检查启动日志，不能把依赖安装成功等同于 SFU 已启用。安装优先下载平台对应的预编译 worker；若开始本机编译，1 GB 服务器可能内存不足，应在相同平台/架构的构建环境准备 worker，参考 mediasoup 的 `MEDIASOUP_WORKER_BIN` 配置，不上传 Windows 的 `node_modules` 到 Linux。
2. 经发布者确认后，在服务器 `.env` 中添加或核对下列字段（本地实现不会自动修改线上配置），将地址改成服务器的公网 IP：

   ```dotenv
   SFU_ENABLED=true
   SFU_ANNOUNCED_ADDRESS=服务器公网IP
   SFU_LISTEN_IP=0.0.0.0
   SFU_PORT=44444
   SFU_EGRESS_MBPS=20
   SFU_RESERVED_MBPS=4
   SFU_VIDEO_MBPS=15
   SFU_PAYLOAD_MBPS=16
   SFU_INITIAL_VIEWER_MBPS=5.5
   SFU_MEMORY_LIMIT_MB=700
   SFU_CPU_LIMIT_PERCENT=85
   ```

3. 云安全组与系统防火墙都放行 **44444/UDP 和 44444/TCP**。如果主机有 NAT，两个协议的外部端口都映射到同一内部端口。网站仍通过现有 HTTPS 反向代理访问；HTTP 反向代理不会转发这条媒体路径。SFU 使用 WebRTC 的 DTLS/SRTP 加密，无需额外把网站证书复制给 worker。
4. 正常启动日志应出现 `[sfu] ready on UDP/TCP 44444`。未填写公网地址、显式关闭、依赖缺失或启动失败时，页面仍可共享，但走 P2P。

**带宽与先到优先策略：**

2026-10-18：默认预算改为针对 20 Mbps 出口；若旧配置仍为视频 22 / 媒体 23，将触发校验，服务器会打印配置错误并禁用 SFU、保留 P2P，直到发布者确认并调整。只修改总出口声明不能扩大真实物理带宽。

AV1 及 P2P 优先（实验）的能力边界、自动化结果和实机验收顺序见 `docs/AV1-SCREEN-SHARING-2026-10-18.md`。

- 默认游戏模式为 1080p60，“桌面文字”默认 30fps；两种模式的发送偏好都保持分辨率，不以主动缩小画面换帧率。浏览器会根据设备与网络调整压缩和实际帧率，目标值不是保证值。
- 15 Mbps 是共享者单份 SFU 视频的高上限，**不是固定码率，也不是每人 5.5 Mbps 的限速**。一两人观看时可按实际需要提高码率，仍受服务器 20 Mbps 物理出口限制。
- 所有频道共用 16 Mbps 媒体预留账本，另保留 4 Mbps 给语音、协议开销、重传及其他服务。`SFU_INITIAL_VIEWER_MBPS=3.5` 用于未知需求的初始预留（另加 0.128 Mbps 共享音频）以及有人等待、无人就绪时的视频上限；有人就绪后使用有效源流视频与音频合计码率加 5% 记账，不再长期保留 3.5 Mbps 最低值。缺测或超过六秒的数据恢复初始预留。15 Mbps 仍是就绪后的允许上限，不是固定实际码率，也不是用户手选的编码起步值。
- 已开始观看时保持配置的视频编码上限，不再根据某个观看者的带宽估计或丢包主动压低整条共享流的码率。不提供低清层或手机降画质档位；浏览器自身的网络拥塞控制仍会决定实际发送码率。无人观看时释放上行预算，接入过程中短暂使用初始码率，开始观看后恢复高清上限。
- SFU 统计连接对象保持稳定，避免每秒重新创建连接标识而重置画质和诊断采样；诊断版本标识为 1.0.5。
- 复用每两秒采样，读取发送源实际码率、去重后的接收 Transport 总出站（含重传/探测）及 Linux 默认出口网卡真实发送字节增量；网卡统计包含其他站点。未知、计数器重置、重复时间戳不冒充真实零值。账本不足、统计失效或观测总出站超过 16 Mbps 时暂停新 SFU 接入，保留已有观看。估算上涨本身不踢人；实际连续三个采样超额才将最新一条订阅回退 P2P，两次释放至少间隔 15 秒。连续三次低于预算 90% 才恢复接入。保留原有接收异常冷却和重试，不平均削减已有观看者的源画质。
- SFU 只有一份编码流。本轮通过优先保留路径实现先到优先，没有为每个观看者生成不同画质。策略是应用层估算与接入控制，不是网卡硬限速；突发码率可能在两次采样之间短暂超预算。
- 15 Mbps 视频加 0.128 Mbps 共享音频，按 5% 余量预留为 15.8844 Mbps，可以容纳一条订阅，不将超额需求截断伪装成预算内。三四人高码率不能保证。`setMaxOutgoingBitrate(16 Mbps)` 仍是每 Transport 的拥塞控制上限；新增的是应用层总量监测与滞回保护，未修改系统或云平台限速，不宣称对瞬时流量的网卡硬限制。默认采用现有 P2P 优先路径，原自动及手动路径仍可选择。发布前历史问题与本次修正见 `docs/SFU-BANDWIDTH-REVIEW-2026-10-18.md`。
- P2P 一两人且没有 SFU 上传时保留原 27 Mbps 高上限；多人或同时存在 SFU 上传时，扣除估计 SFU 上传后再分配直连视频预算。P2P 能否接入仍取决于网络穿透与共享者上行，无法保证任何网络下后来者都获得相同画质。
- CPU、Node 与 worker 内存峰值、系统剩余内存有保护阈值。连续三次资源采样超限会回到 P2P。1 GB 内存是否够用，需要在同时运行其他项目的真实服务器验证。
- 观看端收到并解码 SFU 视频后才停止其重复 P2P 发送。已连接的 P2P 视频 sender 保留空槽，SFU 或整个服务进程停止时可恢复发送；新加入者和需要重新协商的连接仍需要信令服务器恢复。
- 观看端每两秒检查实际解码进度。共享源仍在发送、页面在前台且连续三次低于 5fps 时，释放该观看者的 SFU 路径并恢复原始采集画面的 P2P，不降低分辨率或帧率目标。静止源、后台页面不据此切换；连续三次统计超时也恢复直连。同一共享两分钟内不重试 SFU，避免来回切换。
- 观看者诊断新增“观看路径”和所选媒体连接的 UDP/TCP 协议信息，便于区分服务器转发与 P2P；不导出候选地址。

1. 记录当前 Node 项目的运行目录、启动命令、Node 版本、环境变量、端口和反向代理配置。备份当前程序与 `.env`、`data/`、`cert/`，备份不要放到可公开访问的静态目录。
2. 在现有项目目录之外创建新的版本目录，上传 ZIP 并解压。确认该目录下直接有 `package.json` 和 `src/server.js`，不是多嵌套了一层。
3. 将现有服务器 `.env` 安全配置到新目录，不能用 `.env.example` 覆盖。若 `USE_HTTPS=true`，还要保留 `cert/selfsigned.key`、`cert/selfsigned.crt`；不要擅自改变现有 TLS/反向代理方式。
4. 聊天历史默认在运行目录的 `data/chat-history.json`。建议通过服务器 `.env` 的 `CHAT_HISTORY_FILE` 指向固定的绝对路径，使新旧版本使用同一份历史。如果暂时仍用各版本内的 `data/`，必须停旧服务后再复制最终数据，回滚时也需保留新产生的记录。日志为运行目录的 `logs/node.log`，旧日志保留在旧目录。
5. 在新目录执行 `npm ci --omit=dev`，使用与现有服务一致的 Node 版本。失败则停止发布，不切换。不要上传本机 Windows 的 `node_modules`。
6. 在维护窗口停止旧进程，把宝塔 Node 项目的运行目录改为新版本目录，保持原端口与环境配置，启动命令使用 `npm start`（入口 `src/server.js`）。同一端口不要同时启动新旧进程。
7. 检查启动日志、页面、房间进入、聊天发送、语音加入、双端屏幕共享及实际接收画质。浏览器刷新后验收；仅能打开页面不代表 WebRTC 已正常。

具体宝塔界面因版本和 Node 管理方式而异；不要删除旧 Node 项目或反向代理来代替切换目录。若管理器不支持更改目录，先确认现有启动管理方式再操作。

## 回滚

### 2026-10-12 语音与共享诊断格式 4

- 麦克风设置 →「通话诊断与日志」→「复制双方诊断与本次日志」。共享窗口的「共享诊断」也有同一按钮。所有参与者刷新到当前版本后，任意一方复制即可收集本机及同一语音房间的其他端（最多 8 个对端）。对方无须手动复制；旧版本、超时、离开或切换会话会明确标记。两端各自采样，不保证时钟同步，请比较采样时间。房间收集每 10 秒最多一次。
- 增补请求/实际降噪模式、处理链、AEC 类型与回退、非语音门控、增益和静音、默认/自选设备、浏览器与主版本、音频 RTP 码率/丢包/抖动/样本隐藏/缓冲等待、SFU/P2P 路径事件及视频准备耗时。浏览器不提供的数据保持 null；AudioWorklet 门控确认仅说明功能已启用，不能证明键盘已消失或 AEC 有效。
- 本机自动保存最近 5 次通话（含加入失败的尝试）；每次最多 200 条状态/切换事件，以及前 12 与最近 12 次采样。开始 15 秒每秒采样，之后约每 5 秒；后台放缓。记录被裁剪时标记「截断」。JSON 可查看、下载或清除历史；当前通话清除历史后继续记录。服务器只在点击时转发当前会话，不保存日志或发送其他历史通话。未录音，导出不含原始设备/轨道/Peer ID、IP、候选地址、用户名、聊天或音频内容。页面异常关闭时，结束时间只能记为最后保存时间；浏览器存储不可用时仍能导出当前页日志。
- 远端语音和共享音量独立支持 0–200%；超过 100% 才使用 Web Audio 放大。不支持 Web Audio 输出设备选择时，指定输出设备上的放大退到原生最高 100%，显示恢复提示。放大可能增加削波或扬声器回声；不得把滑块位置当作真实声压或听感证明。真全屏右键菜单挂在全屏容器内。
- 浏览器 AEC 在采集时优先严格请求 `all`，读回实际设置并保留普通 AEC 回退；RNNoise 与浏览器降噪仍互斥。说话混合键盘声仍需要朋友端录音与实机比较；本轮没有替换 RNNoise 模型或加重门控阈值。
- SFU 画面接入时请求一次关键帧；带宽/资源不足退出的订阅有 120 秒冷却，减少反复切换。短期重复相同尺寸/FPS 的 H264 预检可复用 30 秒内完整测量，既有编码选择和画质目标保持原规则。用户先前的稳定诊断证明当时已在 P2P、约 40fps，不能单独证明开始卡顿就是路径切换。

实机复测：两端刷新；不讲话打字 5 秒、讲话打字 5 秒、只讲话 5 秒；外放时让朋友说话并播放视频对比耳机；边讲话边切换麦克风/降噪、静音后再次切换；真全屏右键分别调语音与共享音量；从点击开始共享到稳定后复制一次双方诊断。自动测试与合成音频检查不代表噪声、外放 AEC、游戏帧率或主观听感验收。

停止新进程，将运行目录和启动配置恢复到记录的旧版本，再启动并检查。保留新版本日志以便排查。共享历史文件不要回退旧备份，否则会丢失发布后的聊天记录。如果未来涉及数据格式迁移，先制定兼容与恢复方案，不能只切代码目录。

旧版本目录和 ZIP 经确认后再手动清理，本地打包不会清理任何旧包。
