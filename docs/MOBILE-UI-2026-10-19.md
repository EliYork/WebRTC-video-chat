# 手机界面与操作修复（本地候选版）

## 已修复的问题

- 手机原先默认展开聊天，聊天浮层盖住成员或共享；频道又是另一种覆盖布局。现在使用同一套真实组件，顶部提供频道、语音/共享、聊天三个互斥视图，首次打开默认显示舞台。
- 原 Dock 的姓名、状态、频道、计时器、设备按钮、会话按钮多行堆叠，且宽度固定在左侧留下空白。手机改为有外边距和圆角的紧凑通话卡片，保留麦克风、摄像头、声音、共享及其设置入口、复制链接、加入/离开语音；桌面仍是左下角 Dock。
- 已停止共享的提示不再长期占用手机卡片的一整行；进行中和处理中继续显示。
- 诊断及 Windows 下载收进顶部“更多”。下载明确标明 Windows 64 位。
- 手机共享播放器只直接显示全屏与更多；音量、连接方式、网页内全屏仍可从真实播放器菜单打开。成员姓名与音量操作不再重叠。
- 横屏手机使用画面与成员并排布局，不再误用桌面三栏。判断使用与 CSS 相同的媒体查询；从手机返回桌面恢复原聊天展开状态。
- 麦克风、摄像头、输出设置新增“完成”，触控设备选项加大。加入频道确认层高于导航，窄屏按钮不会撑出视口。
- 聊天输入使用 16px 字体；VisualViewport 缩小时调整聊天可用高度，键盘期间收起卡片上的设备操作行，保留会话按钮。缩放页面不作为键盘处理。
- 通过实际 getDisplayMedia 能力决定浏览器能否选择屏幕；不支持时明确提示仍可用摄像头、语音和观看功能。原生选项明确称为 Windows 客户端共享。

未更改 Piik、ICE、编解码、频道授权、服务端或语音媒体路径。上一轮摄像头关闭后清理残帧的修改保留。

## Android 实机验收

在运行本地候选版的可信 HTTPS 测试站或后续上线版本上验证；当前未部署，现有线上页面不会因此变化。

1. 竖屏首次进入：应显示频道舞台，聊天不覆盖；频道、语音/共享、聊天可直接切换。
2. 频道列表选择频道，取消/确认加入；确认对话框应覆盖顶部导航。检查进入的是选定频道，离开后没有继续通话。
3. 加入后开启、关闭麦克风和摄像头，检查对端画面消失与恢复；上下箭头进入真实设置，“完成”退出。
4. 电脑发起共享：手机观看，切换聊天/频道再返回，画面应继续更新；更多菜单可以调整音量、打开连接方式及网页内全屏。
5. 写入一条未发送消息，切换视图再回来；输入法弹出、收起、切换输入法和手势导航后，检查输入框、发送按钮及会话按钮是否可用。
6. 横竖屏切换、系统大字体、浏览器地址栏展开/收起、安全区和真全屏需要实机检查。合成视口和键盘状态测试不能证明这些设备行为。
