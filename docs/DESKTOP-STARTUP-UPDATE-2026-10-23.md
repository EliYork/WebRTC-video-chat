# 客户端启动更新提醒（0.1.6）

## 行为

- 启动约 3 秒后检查现有 HTTPS 更新源。发现未忽略的可用新版本时打开本地无声更新窗口；主窗口未显示时等到显示再提示。
- **更新**：显式下载，显示真实进度；完成后选择“退出并安装”，仍需再次确认结束通话与共享。不会自动下载、退出或安装。
- **忽略本次**：只忽略当前发布版本，保存到 AppData 的 `update-preferences.json`；下一版本仍提醒。“关于与更新”仍可手动检查和下载。
- **关闭 / × / Esc**：只关闭提示，不记为忽略；下次启动仍可提醒同一可用版本。关闭下载窗口不会偷偷取消或安装。
- 当前启动内同版本最多自动提示一次。每 6 小时的后台检查保持静默；无更新和检查失败不弹窗，客户端继续进入频道。
- 已有关于窗口时复用其状态，不重复弹提示；手动打开关于窗口会收起启动提醒。退出、主窗口更换、等待版本信息期间忽略或开始下载后，迟到结果不再打开启动提醒。

只有受主进程持有的本地面板可以触发检查、下载、忽略和安装。保留 sender/window/mainFrame/本地 URL 验证；远端网页和普通 iframe 没有这些权限。保留安装包 SHA512 校验与 `autoInstallOnAppQuit=false`。

## 验证

- 新增 6 项 Node 回归：启动提示时机/一次性、跨启动忽略、新版再提醒、手动下载、离线/无更新/退出、损坏与写入失败，以及元数据等待期间的取消归属。相关定向共 9 项通过。
- 隐藏静音 Electron 使用真实 `NsisUpdater` 与本机合成更新源，经过 4 次启动检查：关闭后再次提醒、忽略后不提醒、手动仍可更新、新发布版本再次提醒；只有点击更新才下载，拒绝安装确认后安装次数为 0。
- 三个按钮为“更新 / 忽略本次 / 关闭”，面板无横向溢出；未操作用户活动窗口、未执行安装。
- 既有设置窗口检查继续通过：真实进度、取消下载、关闭重开、失败重试、拒绝非持有窗口 IPC 和来源选择器。预期的拒绝日志不代表授权放宽。
- 最终默认并发 `npm test` **778/778 通过**（12.32 秒）。早先完整运行的发布就绪探针因 Windows MSYS fork 报 `0xC0000142 / Resource temporarily unavailable` 失败；测试夹具在 Windows 的单次 Bash 中使用尾部 exec 运行原 Node 探针，保留 HTTP/TLS/体积/8 秒截止断言和默认并发，生产 Linux 脚本未修改。修正后定向 3/3、完整 778/778 通过。

测试：`tests/desktop_updater_test.mjs`、`tests/desktop_update_prompt_test.mjs`、`desktop/windows/test-update-prompt.cjs`、`test-panels.cjs`。

发布状态和下载地址以最新发布记录为准。旧 0.1.5 的静默检查行为不会被网页替换；需先通过原“关于与更新”入口升级到 0.1.6，才具备下次新版的启动弹窗能力。
