# 聊天保存可靠性（2026-10-22，本地候选）

## 完成内容

- 消息接受/广播与历史保存分别报告。`chat:send` 的 `ok: true` 表示消息已被接受，另带 `persistence: { state, revision }`；不把排队写盘标为保存完成，不因写盘失败要求重发。
- 聊天记录在内存中仍按频道保留最近 50 条。磁盘写入使用异步文件 API，40 ms 合并窗口、单个串行写入器、临时文件写入后原子替换。写入中的新增消息进入下一份快照，不会被上一份写入误标为已保存。
- 写盘失败保留旧历史文件和当前内存消息，自动按 2/4/8/16/32/60 秒退避重试。连续故障只记录一次错误；恢复成功后允许下一次独立故障重新报告。新消息不会重复广播或自动重发。
- `chat:persistence` 只发送到对应 `view-chat` 频道；加入/重连时的历史 metadata 带当前保存状态，后来加入者也可看到已有保存故障。事件不包含消息内容、文件路径或底层系统错误。
- 页面提示“部分聊天记录暂未保存，正在自动重试；已发送的消息无需重发”。保存恢复后自动隐藏。保存故障不禁用发送，也不清空新的未发送草稿；跨频道和旧 revision 事件不能覆盖当前状态。连接/发送错误沿用原有优先级。
- SIGINT/SIGTERM 正常停止时关闭信令和媒体服务，并尝试保存排队消息；退出保存失败返回非零退出码，最多等待 5 秒。没有新增独立服务、数据库、配置项或依赖。

## 后续：慢写失败期间保留重试退避

慢写尚未完成时，新消息原本仍会启动批处理定时器。定时器在写入期间到期后排队调用 `persist()`，导致当前写入失败后立即再试，绕过应有的失败退避。`ChatHistoryStore.js` 现在由正在执行的写入统一安排下一次批处理或失败重试，生产退避仍为 2/4/8/16/32/60 秒；显式 `persist()` 和 `close()` 仍可立即尝试保存排队消息。

- 新增回归使用真实临时历史文件和受控的慢速 I/O 失败：写入期间向两个频道追加消息，失败后在退避窗口内只发生一次保存尝试，旧文件保留，两频道均报告保存失败；随后 `close()` 立即发起第二次保存，并从磁盘读回全部待保存消息及恢复状态。
