# 语音处理与试听说明

日期：2026-10-12。当前部署与回滚记录见 `DEPLOYMENT-2026-10-12-WORKSPACE.md`；下文各轮检查结果保留其历史边界。

## 模式切回失败修复

- 真实 Edge 155 复现了 RNNoise 的 WASM 编译被 CSP 阻止。服务器 HTML 与 Worklet 响应的 `script-src` 加入 `wasm-unsafe-eval`，只允许 WASM 编译，继续禁止 JavaScript `unsafe-eval`。此前离线 WASM 和模拟管线测试漏掉了浏览器安全策略这一层。
- 同一浏览器检查还发现，普通布尔采集请求可能复用旧源，使 RNNoise 切到浏览器内置后实际降噪仍关闭。现在对浏览器报告支持的 NS/AGC 使用 `exact` 请求，要求采集源符合模式；格式失败重试也保留这些处理要求和指定设备。设备拒绝时保留旧音频，浏览器兼容性仍需实机检查。
- Worklet 报告有限长度的初始化原因；运行时只映射为安全策略、处理器初始化或采集失败等状态码。设置诊断显示失败目标，成功采用新分支后清除失败。界面不显示任意异常原文或调用栈。
- `npm test` 297 项通过。源码、模式切换浏览器脚本及相关音频/UI 测试 lint 通过，Worklet 语法检查通过；没有修复既有全仓 lint 问题。
- `scripts/verify-noise-mode-switch-app.mjs` 使用真实 HTTP CSP、真实 RNNoise WASM、Edge 假麦克风：8 次运行时往返、6 次加入语音后实际控件切换、连续快速请求、输出轨道/静音保持通过，浏览器读回 NS 与模式一致，人声门控已确认。另用普通 nonce 脚本的异步执行验证 JS eval 被阻止，避免把 DevTools 的 CSP 例外误当浏览器行为。没有替换业务模块、关闭 CSP 或使用物理麦克风。

运行此专项检查可通过 `PLAYWRIGHT_MODULE` 指定已有 Playwright 安装，执行 `node scripts/verify-noise-mode-switch-app.mjs`；`NOISE_TEST_URL` 可指定单独的线上测试房间。默认使用临时目录和随机本地端口，不写项目聊天数据。结果 JSON 保存在输出的临时目录。

这些结果证明指定浏览器中的加载、切换与状态行为，不能证明真实键盘抑制、外放回声或人声听感通过。

## 处理模式

| 模式       | 请求的采集处理                    | Web Audio 分支                             |
| ---------- | --------------------------------- | ------------------------------------------ |
| 关闭       | AEC；关闭浏览器降噪和自动增益     | 用户麦克风增益 → 稳定输出                  |
| 浏览器内置 | AEC + 浏览器降噪 + 浏览器自动增益 | 用户麦克风增益 → 稳定输出                  |
| RNNoise    | AEC；关闭浏览器降噪和自动增益     | 单声道 RNNoise → 可选人声概率门控 → 用户麦克风增益 → 稳定输出 |

“关闭”关闭降噪，AEC 仍请求启用。RNNoise 不叠加浏览器降噪。删除原有固定 1.35 倍放大；默认用户增益为 100%，0% 为真正的零增益，超过 100% 仍由用户选择，较大输入可能削波。最新键盘抑制使用已有 RNNoise 人声概率进行可关闭的平滑门控，没有新增压缩器或大型模型。

## 键盘残留抑制更新

现有适配器此前忽略了 RNNoise `processFrame()` 返回的人声概率。现在在相同 480 样本模型帧内，用该概率控制处理后声音的衰减，不增加新的模型、前视或队列。该功能只作用于 RNNoise，默认开启，可在麦克风设置中关闭对比；诊断显示处理器实际确认的开关状态。

- 高人声概率快速恢复音量；低人声概率的稳态衰减上限为 40 dB，这是门控增益参数，不是实测键盘消除率。
- 不确定的人声概率采用渐进衰减，不硬静音；使用约 3 ms 开启斜坡、180 ms 尾音保持和 80 ms 关闭斜坡，减少爆音和尾音截断。
- 开关通过同一个 Worklet 的消息端口生效，不重采集、不更换发送轨道；设备或模式切换采用最新偏好，保持静音。旧版处理器未确认能力时，不报告键盘抑制已开启。
- 主要针对不讲话时的键盘/敲击残留；说话期间门控需要保留人声，此时残留仍依赖 RNNoise 本身。低声、气声或首字识别不充分时可能变弱，可关闭开关比较。它不替代 AEC，也不消除播放中的其他人声。
- 295 项全量自动测试通过；源码和涉及测试文件 lint、模板及 Worklet 语法检查通过。真实 WASM 离线测试覆盖合成短促宽带敲击的额外衰减、有效 VAD 与既有帧调度；没有把合成测试当作用户键盘或真实说话验收。

接口参考：[RNNoise API](https://github.com/xiph/rnnoise/blob/main/include/rnnoise.h)。VAD 阈值、尾音保持与附加延迟之间的工程取舍可参考 [RNNoise 插件说明](https://github.com/werman/noise-suppression-for-voice#plugin-settings)；本项目使用独立的平滑门控实现。

浏览器对请求的执行情况取决于采集设备、浏览器和操作系统。麦克风设置内显示请求模式，以及物理麦克风轨道 `getSettings()` 读回的 NS、AEC、AGC。未提供的设置显示“未报告”，不把请求值作为生效证据。读回 “all” 只证明浏览器报告该模式，不证明外放回声消除效果。

## AEC 选择与限制

1. 正常获取设备时请求普通 `echoCancellation: true`，保持指定设备约束。
2. 检查 `getSupportedConstraints()` 和物理轨道 `getCapabilities().echoCancellation`。能力明确不包含 `all` 时跳过；能力未报告时尝试严格 `exact: 'all'` 探测。
3. 读回设置。只有实际为 `all` 才显示系统播放声音模式；拒绝、忽略或未报告时恢复普通 AEC 请求，并显示回退。
4. 浏览器降噪被报告为开启、但当前模式要求关闭时，严格要求 `noiseSuppression: false`。无法关闭则拒绝切换并保留旧分支，不悄悄叠加 RNNoise。
5. 只在采集格式/约束失败时重试较简单的约束，保留指定设备。权限拒绝、找不到设备、设备占用不会自动换麦克风或反复请求权限。

AEC 在浏览器采集端处理，随后才进入应用的 RNNoise/增益；共享系统音频保持原来的独立传输。没有新增播放参考采集、自定义 AEC、LocalVQE 或服务器音频处理。

标准参考：[AEC 模式定义](https://www.w3.org/TR/mediacapture-streams/#dom-echocancellationmodeenum)。`true` 由浏览器选择消除范围；`all` 要求尝试消除系统播放声音。实际设备可能不支持或消除不充分，尤其是大音量、扬声器失真、房间反射和同时讲话。

## 实时切换与资源所有权

- `voice-audio-settings-controller.js` 管理模式和设备的共同请求版本、已提交设置和失败回退，旧请求不能覆盖新选择。持久化模式在成功后更新。
- `voice-audio-processing.js` 管理采集、AEC 检测、WASM 初始化、内部处理分支、读回诊断和资源释放。采集与初始化串行，过时请求跳过，减少重复设备请求。
- 正常切换复用运行中的 AudioContext 和发送端输出轨道；只把准备好的新分支接到原目的节点，然后销毁旧分支。静音留在对外输出轨道上；设备切换不解除静音，不触发视频或共享重新发送。
- 捕获新的采集分支时，浏览器可能共享同一硬件源的处理设置。失败时恢复旧分支设置，并显示恢复异常，避免把仍然有轨道误认为完全恢复。
- 拔出原始麦克风由原始轨道的 ended 事件监测，包含静音状态。默认设备恢复保留静音。设备权限或硬件独占可能使新采集失败；已有可用音频优先保留。
- RNNoise 使用已有资源，首次选择时加载，二进制和每个 Context 的 Worklet 模块缓存。初始化有 ready/error 确认与超时，切离 RNNoise 时销毁处理器。更改挂断状态会撤销待处理请求；无法取消浏览器权限对话框，但迟到的采集会被释放。
- 运行中 RNNoise 异常且 Context 仍正常时，在同一输出轨道上旁路并显示回退。Context 无法恢复时沿用已有原始采集恢复路径；这种异常恢复可能替换音频轨道，不能保证完全无声间隙。
- 扬声器沿用已有每播放器串行 `setSinkId()`、重复请求合并、版本检查及默认设备回退；没有改变 SFU/P2P、视频编码或共享音频策略。

旧的“重进房间后生效”通知已移除。模式下拉与原有按钮都选择同一套互斥模式，诊断区显示切换中或恢复原设置。没有正在采集的麦克风时保存偏好，下一次开启麦克风使用该偏好。

## 用户实机试听

准备另一台设备/另一位观看者监听，避免两端都开扬声器形成额外反馈。发送端从 100% 麦克风增益开始，固定麦克风距离和播放音量；每轮记录浏览器版本、请求模式、实际 NS/AEC/AGC。

### 键盘、风扇、敲桌子

依次选择关闭、浏览器内置、RNNoise，每种保持相同条件约 20 秒：

1. 不讲话时打字、开风扇、轻敲桌子，比较残留噪声。
2. 持续讲话同时打字，检查首字、尾音、轻声是否被吞，是否出现水声、金属感或音量忽大忽小。
3. 降噪关闭时仍有 AEC，不把这个样本当完全原始录音。纯净环境也听一遍，比较自然度。

### 音箱外放与共享重复声音

1. 发送端共享带音频的视频/游戏，使用中等扬声器音量；先不要讲话。
2. 接收端先只听共享原声，再暂时静音共享音频、只听发送端麦克风。第二种情况下的游戏/视频声是麦克风回传的残留。
3. 恢复共享音频和麦克风，检查是否听到两份内容、拖尾或回声。
4. 换成含人声的视频，再由发送端同时讲话，检查自身人声是否完整自然。也测试其他房间成员讲话的回声。
5. 分别记录实际 AEC 为 `all`、普通开启或未报告时的结果。共享视频必须正常传递原声，不能通过压低共享音量来假装消除麦克风回声。

### 边讲话边切换与失败恢复

1. 保持语音和屏幕共享，连续讲话，快速切换三种模式，以及两个麦克风/两个输出设备。最终模式和设备应与最后选择一致，观看者画面和共享原声持续。
2. 先静音麦克风，再切设备和模式；接收端不应听到声音。解除静音后应能正常讲话。
3. 切换中拔出 USB 麦克风/耳机，观察默认设备回退；再次插入后手动选择。不要依赖浏览器的默认设备行为一定相同。
4. 权限拒绝、设备占用或 RNNoise 资源加载失败时，核对原音频仍可用、请求选择回退、诊断说明失败；从未有可用管线时检查明确的回退/错误状态。
5. 切换中离开频道再加入，迟到任务不得恢复旧频道音频、改变静音或覆盖新设置。
