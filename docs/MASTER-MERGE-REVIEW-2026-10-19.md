## 有依据的问题与修复

### 1. 取消/离开时迟到回执可造成未处理异常

`integrations/piik/client.ts` 的发布取消、观看取消分支原先以 `void request(close)` 清理迟到 session，却没有处理拒绝。离开语音后，服务端合法返回 voice-owner-missing；此清理请求原本会变成 unhandled rejection。

现在明确处理这类尽力清理的失败，仍发送关闭请求，不让清理失败恢复旧共享或影响语音。使用真实适配器、隔离的协议/采集替身延迟回执复现：原代码两个用例失败，修复后通过。

### 2. 断线命令会进入 Socket.IO 重连缓存

同一适配器原先不检查 socket.connected。断线期间的发布/清理命令可能积压并在另一次语音会话恢复后才发送，或额外等待 8 秒。

现在断线时立即拒绝，不写入重连队列；现有发布代次、服务端成员权限和恢复机制继续保留。针对用例在原代码失败，修复后通过；实际隔离浏览器的信令重连回归也通过。

### 3. 旧全量部署工具不适合重复更新融合版本

`scripts/deploy-piik-server.py` 中确认并修复：

- 候选 Go 原先使用生产 TCP 17887 / UDP 3478，并可能把生产 Go 的健康误认为候选健康。现在使用独立回环端口、独立内存房间库，关闭候选托管 STUN；网关检查明确连接候选。候选 Node 也分配独立端口、聊天文件，继承现有配置以免意外启用 SFU。
- 激活原先只执行 pm2 start，已有 Go 注册项可能仍使用旧二进制。现在全量更新时明确替换该 Go 进程；不触碰其他 PM2 应用。
- 回滚原先固定关闭 Piik 并写入早期 56d344d 构建号。现在恢复备份中的实际 Node 构建、绑定地址、Piik 开关，以及原 Go 环境/资源限制/运行状态；旧非融合基线不会凭空启动 Go。
- 完整性校验在停止服务之前完成；候选日志句柄在所有退出路径关闭。

五项临时文件系统/模拟进程回归涵盖融合基线、旧基线、原 Go 已停止、备份损坏拒绝、候选与生产隔离。旧脚本复现四项失败、无 fixture 错误；当前五项通过。没有在真实 Linux/PM2 或生产执行本轮修改的部署工具，不能把这些检查描述为新的生产演练。

服务器私有备份中已经保存的旧脚本副本没有被改写。上一轮 UI 上线所用 `deploy-ui-update.py` 与现有独立回滚入口也未更改。
