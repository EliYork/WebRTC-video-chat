# 语音频道加入与离开提示音

发布状态（2026-10-19 更新）：已上线到网页构建 `904f5a67cec1caa42ebf8c05e0a0ffcb3599bd66`，客户端更新源已发布 0.1.4；用户已安装客户端未自动升级。未提交或 Push。完整记录见 [部署报告](DEPLOYMENT-2026-10-19-DESKTOP-014.md)。

## 使用

- 自己加入成功以及当前语音频道有其他成员加入：柔和的 do–re（C5 → D5）。离开：re–do（D5 → C5），每次约 0.3 秒。
- Dock 的声音下拉菜单提供「成员加入 / 离开提示音」和独立音量，默认开启、35%；偏好按当前浏览器/客户端保存。
- 跟随总静音、输出音量和选定输出设备。提示音通过独立的 Web Audio 节点播放，不加入麦克风或 WebRTC 发送流；若共享整个系统声音，操作系统仍可能将提示音采集进去。
- 初始成员列表、重复快照、摄像头/静音更新、仅浏览别的频道、本机断线恢复不补播；同一批成员变动限频，避免连续叠音。
- 若选定输出设备不可用，或浏览器不能将提示音路由到该设备，则跳过提示音，不擅自改从默认扬声器播放。浏览器阻止自动播放时等待真实用户操作恢复，不积攒旧提示。
- 网页关闭/刷新直接释放提示音资源，不尝试补播退出音；客户端退出窗口与托盘操作不播放频道提示音。真正离开语音频道时才播放离开音。

## 2026-10-22 输出切换期间取消旧提示音（仅本地，未部署）

原提示音队列只在静音或关闭提示音时使播放 revision 失效。设备 A 正在切换、成员提示音排在其后等待时，再切换到 B 或选回默认设备，旧提示音可能等待最新路由完成后补播。旧路由完成时也会恢复非零 master 增益，即使它尚未匹配当前设备选择。

`voice-channel-sounds.js` 现在记录最近请求的设备；选择变化时使旧播放请求失效并停止旧音符，包括“实际切换尚未完成，用户又选回当前设备”的情况。路由完成后重新检查最新选择，只有匹配时恢复 master 增益；销毁后迟到完成不再更新路由。播放请求在同步检测当前输出选择后取得自己的 revision，使当前选择下的新事件仍能正常播放。同一设备的重复同步不取消最新事件。已发出的原生设备切换仍按原队列等待，不承诺取消系统 API。

- 新增 4 项 Node 回归：等待中换到第二设备；等待中选回默认；旧路由完成至最新路由就绪期间保持 master 静音；同一等待设备重复同步仍播放最新事件。旧实现 **7/10 通过、3 项失败**；修复后与远端输出及放大播放定向 **30/30 通过**。
- 复跑已有隐藏静音 `desktop/windows/test-channel-sounds.cjs`，Chromium OfflineAudioContext 两种音序、包络、约 0.05575 峰值及尾部归零检查通过，结果为 `integrations/piik/artifacts/channel-sounds.json` 的 `passed=true`、`offlineOnly=true`、`muted=true`。路由时序由受控 `setSinkId` 验证，离线波形不证明物理路由或听感。
