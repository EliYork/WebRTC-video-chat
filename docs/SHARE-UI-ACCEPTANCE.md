# 共享交互修复与本地验收

日期：2026-10-19；分支：`codex/piik-integration`。用户随后授权上线，源码 `6b2540b` 已部署到生产网页；未合并或 Push。已安装客户端刷新后使用新页面，无需重装；见 [部署记录和回滚](DEPLOYMENT-2026-10-19-SHARE-UI.md)。未改 Piik 上游固定版本 `9925486cec9910c0a76e47208b29b6f39942e096`。

## 修复依据

- `stage-layout.css` 原网格把 Dock 横跨三列；现在真实 Dock 只占左栏下方，中央与聊天使用释放的高度。没有复制 Dock 或另造 fixed 控件。
- 共享窗口原先继承设备菜单的 300px 宽度、位置及 `#buttons button` 的 28px 高度；现在用居中的原生 dialog、固定可用的页脚和可滚动内容，独立覆盖菜单按钮样式。共享状态原先还触发五列按钮规则及绝对定位状态标签，现已消除这两处冲突。
- 原实现把共享中的设置全部禁用，且没有来源修改 action。现在 Dock 箭头与舞台按钮进入同一个编辑器，按成功回执更新当前共享状态；没有另建媒体路由控制器。

## 现在的交互

1. 加入语音，点左下角「共享」。默认网页共享；选择「客户端原生共享」可看到按屏幕、窗口分组的真实缩略图卡片。
2. 选择卡片、分辨率和 FPS 后开始。码率、编码等在高级设置；来源声音默认关闭。选择整屏声音会明确提示可能包含本频道声音。
3. 共享中，Dock 主按钮直接停止；其箭头打开同一来源编辑器。舞台上还有「更换画面」「画质」「停止共享」。
4. 更换来源或改画质后点击确认。处理期间防止重复提交；如要取消已开始的媒体操作，使用「停止共享」。正常关闭/取消编辑器只释放来源预览，不停止当前共享。
5. 失败会留在编辑器显示错误；取消浏览器来源选择器保留旧共享。停止后观看者返回成员舞台，语音与聊天保留。

## 实际能力和边界

| 操作 | 原生共享 | 网页共享（融合版） |
| --- | --- | --- |
| 来源预览 | 调用上游 `NativeClient.sourcePreview`；有权限后才请求 | 使用浏览器原生选择器，不枚举网页无权访问的窗口 |
| 切换来源 | 上游 `replaceShareSource`，保留共享/媒体连接身份 | 先取得新来源权限；取消保留旧共享；确认后关闭旧发布再发布新流 |
| 分辨率/FPS/码率 | 上游 `updateShare`，等待确认 | 对采集轨道应用上游 profile，并更新真实 HostPeer 发送参数 |
| 音频或共享方式变更 | 受控重建，画面可能中断 | 受控重建；改变编码也需重建 |
| 停止 | 关闭 Piik 发布、原生 share、预览与采集资源，通知观看者 | 关闭 Piik 发布与采集轨道，通知观看者 |

- 原生保持 H.264 硬件路径，无 AV1 移植或新 SFU/转发功能。是否实际选择 NVIDIA，要以真实机器日志为准。
- 原生切换/画质更新保持媒体会话，但 Piik 内部可能准备并替换采集/编码进程，会短暂冻结画面；不会将两路共享同时发布给观看者。更改失败会尝试恢复旧 profile，恢复失败则停止该共享。
- 原生只支持明确的 720p/1080p/1440p/2160p 目标；「自动」「原始分辨率」会在启动前提示，不静默降分辨率。实际输出能力取决于源、设备和接收端。
- 缩略图是按需快照，不是持续播放。每组每页三项、合计最多六项，逐项请求；刷新/翻页才重取。关闭、换模式、停止或离开时取消选择器连接及待处理请求，独立于正在共享的连接。
- 受保护、关闭或不能预览的窗口显示明确的不可用提示；仍可选择可用来源，不伪造截图。刷新会清除消失来源的选中状态；开始和切换时重新核验完整来源身份（包括窗口进程及创建时间）。
- 码率是上限、FPS 是目标，不是保证的实测值。低分辨率源不能通过设置获得真实 4K 内容。
- 原生声音取自所选应用或系统，没有新增自动通话声音排除承诺。整屏音频可能回传通话；默认关闭。
- 旧网页媒体路径保留回退。旧路径修改画质采用明确提示的重建流程，浏览器会重新要求来源授权。
- 网页从限定分辨率改为「原始分辨率」会明确提示重新选择来源，避免把已经缩小的采集设置误当成原始屏幕尺寸。

## 在本地手动验收

本轮没有打包或替换当前客户端。使用已有隔离启动器，可验收本工作树的真实页面和原生 App；完整环境与 Android 可信 HTTPS 步骤见 [现有 Windows + Android 指南](../integrations/piik/ACCEPTANCE.md)。

```powershell
Set-Location 'C:\Users\EliYork\.codex\worktrees\piik-integration\WebRTC-video-chat'
npm run dev:piik:acceptance
```

由你打开打印的开发地址，另一个浏览器/设备进入同一频道。启动器不打开浏览器、不开始捕获。`q` 回车或 `Ctrl+C` 只停止这次的三个测试服务。

1. 在 1920×1080、2560×1440、3840×2160 检查未加入、语音中、共享中及收起聊天四种状态。Dock 始终在左下；无共享时中央仍为成员舞台；聊天保持右侧。
2. 原生模式检查屏幕/窗口缩略图、选中描边和来源名称；打开新窗口再刷新，关闭已选窗口后刷新，确认不能提交失效来源。关闭选择窗口后继续通话。
3. 先以 1080p60、声音关闭开始。观看者应在原舞台看到画面。持续说话和发送聊天，切换到另一个窗口，检查只有一路共享且没有旧窗口残留。
4. 点「画质」改 FPS、分辨率、码率，并对照实际诊断/原生日志。再测 1440p60 和 4K60；物理硬件与 Android 的实际性能需要实机验证。
5. 用舞台按钮停止；确认其他人画面退出、语音继续、采集进程释放。再用 Dock 重开与停止。多共享者时停止自己的共享不能影响其他人的共享。
6. 网页模式重复测试：浏览器来源选择取消、确认切换、画质更新、停止和重开。取消来源选择时，旧共享应继续播放。
7. 原生共享中只打开来源选择器、不确认就关闭，应继续共享；改声音或共享方式会提示重建，确认后检查无重复发布。掉线/刷新后没有幽灵共享。
