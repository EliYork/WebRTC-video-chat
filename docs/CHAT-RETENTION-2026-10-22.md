# 长时间聊天的页面保留窗口（2026-10-22，本地候选）

## 问题与改动

当前服务端每频道仅保留最近 50 条历史，但已打开页面的实时消息 DOM、消息 ID 去重集合、等待历史返回期间的实时消息队列此前持续增长。新增回归在旧实现分别得到 2000 和 1600 条 DOM 行，均未裁剪。

本轮为当前页面设置明确窗口：

| 状态 | 上限与行为 |
| --- | --- |
| 已渲染消息 | 最近 500 条；移除更早的页面节点，裁剪后在列表顶部显示一条“此页面仅显示最近 500 条消息。” |
| 近期消息 ID | 最多 1000 个；重复消息不再显示或触发实时通知。窗口之外的旧 ID 不提供永久去重保证。历史重新渲染时沿用既有重置语义，只记录当前可见消息。 |
| 等待历史期间的实时消息 | 最多 500 条，历史与待处理实时消息按 ID 合并后再保留最近 500 条。 |
| 清空、切换频道及销毁 | 清理对应去重和待处理记录；渲染器的滚动补偿记录使用 WeakMap，不持有已释放容器。 |

保留窗口只作用于当前浏览器页面；没有修改服务端历史文件、每频道 50 条保留策略、发送协议或保存状态。页面不提供被裁剪消息的分页恢复或完整聊天归档。没有新增自动重发或恰好一次消息交付保证。

## 阅读位置

收到新消息时，若用户原本在底部，继续跟随最新消息。用户向上阅读时，裁剪前记录一条仍将保留的可见消息，裁剪后补偿其在列表视口内的位置。聊天容器关闭原生 scroll anchoring，由渲染器负责裁剪补偿；保留小数像素的余量，避免连续裁剪时滚动偏移取整累积。

若当前阅读的消息本身已超出 500 条窗口并被裁剪，则页面只能显示剩余窗口及其顶部提示，不能继续保持已移除节点的位置。

## 后续：同频道历史刷新保留阅读位置

此前 `renderChatHistory()` 无条件滚到底部，导致向上阅读时发生重连、刷新当前历史后离开原阅读位置。

配套更新 `chat-panel-runtime.js` 与 `chat-message-ui.js`：runtime 向渲染模型传递已有稳定消息 ID，并启用历史刷新阅读保护；renderer 在替换记录前找到仍包含在新窗口中的可见消息，替换后补偿其相对列表视口的位置，保留小数像素余量。ID 仅以节点为 key 存在 WeakMap 中，不增加 DOM 属性、消息协议或持久化状态。

原本在底部时继续跟随最新消息，首次加载及切换频道仍显示最新。若当前可见消息不在新窗口中、没有稳定 ID 或无法恢复锚点，则回到剩余列表顶部，不能重建服务器未返回的旧消息；服务器仍只返回最近 50 条，页面仍最多 500 条。

## 后续：关闭聊天期间裁剪或刷新后仍恢复同一阅读消息

此前舞台只保存关闭时的 `scrollTop`。聊天隐藏期间仍会接收消息、裁剪超出 500 条窗口的旧行，或者重新加载当前历史；重新打开时，旧像素位置会指向另一段内容。

`chat-message-ui.js` 提供阅读位置捕获与恢复接口：关闭前记录可见消息的稳定 ID、相对列表顶部的偏移和原始滚动位置；重新显示后按当前消息节点恢复，并保留像素取整余量。舞台使用该接口处理显式关闭及宽屏进入手机布局后的恢复，不持有旧消息 DOM 节点，也不额外缓存历史。原阅读消息已不在当前窗口时回到剩余列表顶部；无可识别锚点时保留原像素恢复。首次打开、切频道清理及未读规则不变。
